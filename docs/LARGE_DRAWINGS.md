# 대용량 도면

v2.1.7부터 DWG/DXF 원본 512MiB, 변환된 DXF 1GiB를 허용합니다. 앱 보관함은 같은 원본 한도를 적용합니다. 변환 캐시는 2GiB/8개, 화면 준비 캐시는 바이너리 합계 2GiB/4개 및 항목당 1GiB입니다. 캐시의 메타데이터와 브라우저 저장소 오버헤드는 이 바이너리 예산과 별도이며 실제 저장 가능량은 기기의 여유 공간·브라우저 저장소 정책에 달려 있습니다.

단위·주석 식별은 기존 v1 전체 내용 지문을 유지하며 1MiB씩 순차 처리합니다. 캐시가 부족하면 생성 캐시만 LRU로 정리하고 원본·보관함·주석은 삭제하지 않습니다. 저장소 오류는 캐시를 건너뛰며, 읽기 중 메모리 부족 때는 즉시 다시 전체 파싱을 시작하지 않습니다.

DXF는 기존 엔티티 파서·렌더러를 유지하되 전체 문자열 split 줄 배열을 만들지 않습니다. 디코딩한 청크에서 필요한 줄만 생성하며 최근 줄과 작은 체크포인트로 peek/rewind를 지원합니다. 파일 전체를 메모리에 전혀 올리지 않는 파서는 아닙니다.

LibreDWG의 고정 버전 0.9.0 런타임에서 모든 메모리 확장 시도가 실패하면 C 코드가 null 할당 결과로 진행하기 전에 DWG_MEMORY_LIMIT를 반환합니다. 변환은 별도 일회용 프로세스에서 직렬 실행됩니다. Android가 그 프로세스를 종료해 ResultReceiver 응답이 사라져도 감시기가 대기 중 요청을 끝내고 임시 파일을 회수합니다. 변환과 표시 준비는 최대 10분이며 취소할 수 있습니다. 표시 렌더러가 종료되면 원본 열기 Intent를 재실행하지 않고 초기 화면으로 복구합니다.

## 확인된 범위

제공 시험 DWG: 46,282,731바이트 → DXF 357,093,775바이트. PC 및 임시 64비트 LDPlayer 진단 변환 결과 SHA-256이 일치했습니다. 64비트 진단 실행에서 표시·한글을 확인했고, 생성된 727,154,370바이트 화면 캐시는 표준 32비트 LDPlayer에서 약 7.8초에 다시 열렸습니다. 기본 32비트 WebView의 최초 변환/화면 준비는 메모리 한계에 도달했고, 이 도면의 측정 인덱스 제한도 남아 있습니다. 전체 도면 측정 PASS가 아닙니다.

기존 BASE/COVER는 기본 환경에서 연속 열기·한글·스냅·960mm/600mm 측정 및 이전 저장 데이터 19개 보존을 확인했습니다. 변환 프로세스 강제 종료 및 WebView 종료 후 복구를 확인했습니다.

100MB 이상 실제 DWG는 아직 없으므로 열기 성공을 보장하지 않습니다. 파일 크기 한도만 확대해도 DWG의 압축 해제 배율, 블록/해치 수, WebView의 32/64비트 주소 공간, JavaScript/WASM/GPU 메모리 한도는 남습니다. 64비트 WebView와 충분한 RAM의 실기기에서 현장 도면을 추가 검증해야 합니다. PDF·압축파일 안전 한도는 변경하지 않았습니다.

v2.1.8에서는 화면 캐시 ID에서 빌드 플랫폼의 줄바꿈을 포함한 worker 소스 URL을 제거했습니다. 명시적 준비 형식 버전·원본 내용 지문·변환 버전이 같은 기존 캐시도 복사 없이 읽습니다. 준비 형식이나 geometry/font/snap 의미가 달라지면 preparedSceneCache.VERSION을 올려야 합니다.
